# Optimization Options

Round-trip savings are counted from the code; seconds use this environment's measured ~0.12 s per round trip. The UAT server's per-trip latency looks higher (see `timing-breakdown.md`), and **every option scales linearly with it**.

## Latency sources, classified

| Source                                                                      | Class                                | Why                                                                                                                |
| --------------------------------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| Pre-toast phase: 10–15 s observed vs ~1.6 s modeled for 13 round trips      | **P0 — dominant, cause UNCONFIRMED** | Most likely a dev-mode compile (53 s cold measured here) or much higher latency in the UAT environment; see step 0 |
| No visible feedback during the wait + success toast before the page changes | **P0 — demo blocker (perception)**   | 10–25 s with only a disabled switcher button is unacceptable regardless of backend speed                           |
| 44 strictly serial round trips per switch                                   | **P1 — meaningful**                  | Fully explains the post-toast 5–10 s phase at ~0.2–0.3 s/round trip                                                |
| Page rendered twice (navigate page-only, then refresh full tree)            | **P1**                               | ~12 wasted serial round trips                                                                                      |
| Duplicate `getUser` (11 per switch; 3 needed)                               | **P1**                               | ~8 wasted Auth round trips                                                                                         |
| Layout awaits 4 independent loaders serially                                | **P1**                               | ~3–4 serial round trips per full render                                                                            |
| `loadAdminContextV2` re-fetches getUser + users + avatar                    | **P1**                               | 3 round trips per full render                                                                                      |
| `HomeScopeBoundary` wasted render (switch started on `/dashboard/start`)    | **P2**                               | Extra server load, not serial latency                                                                              |
| Cookie-write re-render in the action response                               | **P2 / occasional**                  | Only on token refresh                                                                                              |
| DB query cost (<60 ms total under RLS)                                      | **NOT RELEVANT**                     | measured                                                                                                           |
| React Query invalidation / revalidatePath / permission recompilation        | **NOT RELEVANT**                     | none in the path                                                                                                   |

| ------------------------ | --------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Today                    | 44                                            | ~5.3 s (plus the unexplained pre-toast remainder in UAT)                                               |
| After P0 only            | 44                                            | same real latency; instant feedback; pre-toast remainder removed **if** step 0 confirms a compile cost |

| + P1-C2                  | ~16 + document load                           | ~2 s                                                                                                   |

**The 1–3 s target is realistic** with P1 applied _and_ app-server-to-Supabase latency near what was measured here, which is typical for a production deployment in the same region as Supabase. At 0.2–0.3 s/round trip, P1 still leaves ~4–7 s; then the immediate-feedback UX (P0-A) carries the demo.
