## What changed, and why

| #   | Change                                                                                                                             | Reason                                                                                                                                                                                                                                                                                                                                                                                 |
| --- | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Dropped P0-B (dev compile) as an explanation of the pre-toast delay**                                                            | UAT is Vercel production. Dev compile is not a factor                                                                                                                                                                                                                                                                                                                                  |
| 2   | **Added the router action-queue contention hypothesis (H1)**                                                                       | Verified in Next 16.1.7 `dispatchAction`: server actions serialize. The status-bar poll fires a 13-call server action on every window focus/visibility change and every 30 s. `PermissionsSync` fires a server action on every mount (no `initialData`). The previous audit said "Retries/invalidation not a factor" but never considered **other actions queued ahead** of the switch |
| 3   | **Added the deployment-topology term (region)**                                                                                    | No `vercel.json`/`regions` in the repo, so the default `iad1` is likely, against Supabase eu-west-1. The previous audit framed latency as "UAT environment latency" of a Cloud Workstation. The multiplier is now the #1 lever, as a config decision (Stage 1)                                                                                                                         |
| 4   | **Replaced "P1-C1 / P1-C2 (skip replace on /start; full-document navigation)" with a single-request `redirect()` from the action** | Verified in `action-handler.js:226-290`: an action redirect streams the target's **full tree** in the same response. That gives one request and one render from any route, without a full reload (P1-C2) or a route special-case (P1-C1). A full-document switch is kept only as the fallback (ALT-3)                                                                                  |
| 5   | **Found the sessionStorage override trap (R5)**                                                                                    | `_providers.tsx:55-89` overrides the server branch with the per-tab session branch. The previous audit's P2-H ("defer `setActiveBranch` until after navigation, relying on providers hydration") would, **as written, flip the tab back to A**. This review replaces it with an explicit `switched` handshake                                                                          |
| 6   | **Redefined "success"** as "branch-B shell committed". Tied to the hydration commit, not to `isPending`                            | The previous audit tied the toast to the end of the transition. That's correct for the current flow, but fragile with `redirect()`                                                                                                                                                                                                                                                     |
| 7   | **Rejected P2-I (a lighter authorization-only loader for `changeBranch`)**                                                         | It would create a second path for the Zone 1 invariant for ~1 serial step once the loader is parallel                                                                                                                                                                                                                                                                                  |
| 8   | **Added background-read migration** (poll → GET Route Handler; `PermissionsSync` seeded from SSR)                                  | Follows from #2                                                                                                                                                                                                                                                                                                                                                                        |
| 9   | **Performance targets restated as production p50/p95, cold vs warm, plus honesty rules**                                           | The previous audit's "1–3 s target" didn't separate warm and cold, and had no UNACCEPTABLE line                                                                                                                                                                                                                                                                                        |
| 10  | Noted the second `changeBranch` caller (cross-branch QR confirm) must follow the same design                                       | The previous audit only covered the sidebar switcher                                                                                                                                                                                                                                                                                                                                   |

## Net effect on the plan

- Previous plan: UX fix → (dev-compile fix) → 5 incremental trims → maybe a full-document navigation. It projected ~22 serial calls and 2 renders.
- This plan: measure → co-locate → UX + remove queue contenders → single-request switch → trims. It projects ~14 serial steps, 1 render, and no queue wait.
