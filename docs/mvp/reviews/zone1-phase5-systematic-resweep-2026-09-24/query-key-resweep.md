# Zone 1 / Phase 5 — Query-Key Factory Re-Sweep

Every module under `apps/web/src/hooks/queries/` inspected for branch-scoped list data with a static (branch-agnostic) key.

## Method

For each query-key factory module, asked: does the underlying data depend on active branch? If yes, does the key encode branch identity? Classified per the task's own required scheme: SAFE — unique object/session ID; SAFE — explicit branchId; SAFE — org-scoped by design; BUG — branch-scoped list with static key; UNVERIFIED.

## Verdict

Zero BUG classifications found. Every branch-dependent query in the app already encodes branch identity explicitly in its key (either pre-existing-correct or fixed by Phases 2-4). Every org-scoped classification is a deliberate, already-accepted product design (org-wide administrative lists, or entity-ID-scoped reusable infrastructure), not an oversight. One AMBIGUOUS item (Help Desk tickets list) is a pre-existing, already-known, already-deferred PILOT-scope product decision — correctly left alone.
