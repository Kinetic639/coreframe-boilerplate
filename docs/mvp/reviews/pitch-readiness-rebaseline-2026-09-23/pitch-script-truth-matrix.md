## Receiving/putaway pitch-blocker determination

**CONFIRMED: YES, this is a genuine presentation blocker, not a deferred nice-to-have.**

Exact script language (`ambra-skrypt-prezentacji.md`, §7 "PRZYJĘCIE I ROZKŁADANIE DOSTAWY"):

> "PRZEJDŹ NA TELEFON. ... DEMO: **SKAN CZĘŚCI/ZESTAWU → SKAN LOKALIZACJI → POTWIERDZENIE** ... Skanuję część albo zestaw. Następnie skanuję etykietę lokalizacji, na której ją odkładam. Potwierdzam. I przechodzę do następnej. System na bieżąco wie, co zostało już rozłożone, gdzie się znajduje oraz czego jeszcze brakuje do zakończenia dostawy. ROZŁÓŻ KILKA POZYCJI. ZAKOŃCZ SESJĘ. WYGENERUJ RAPORT."

Reinforced independently by `mvp-readiness-full-vision-pitch-script-refactored.md` ETAP 11: **"To jeden z kluczowych momentów demo"** (one of the key moments of the demo), listed as a mandatory live-demo item.

Code verification: `receive_repair_order_stock`/`putaway_repair_order_stock` exist and are actively maintained (touched as recently as `20260922110722_a8_putaway_live_attribution_check.sql`) but have **zero TypeScript callers anywhere in the repository**. The two mobile routes the script's demo would need (`/warehouse/deliveries`, `/warehouse/scanning/delivery`) both still render a generic `WarehousePlaceholderPage`.

**There is no code path today that a demonstrator could open on a phone to perform this exact flow.** This updates and supersedes the Inventory Core Final Pilot Freeze bundle's own earlier framing ("receive/putaway UI blocks pitch ONLY IF the pitch demos receiving") — **the current pitch script definitively does demo it, so this is unconditionally a presentation blocker**, not a conditional one.

## 201/WZ issue design consistency

**CONFIRMED gap, consistent with Zone 7's own investigation.** No `201`/WZ document type is live. `issueStockAction` is a hardcoded stub. The master tracker's own "Otwarte decyzje zakresu" item #4 explicitly recommends AGAINST using 402 as a substitute ("Nie używać 402 jako trwałego rozwiązania w żadnym wypadku") — this decision remains open and unresolved. The current master script itself stays deliberately abstract about the exact document type used ("zarejestrować wydanie"), which is honest framing — but if a demonstrator improvises this step live via the only working path (the generic movement editor), they will almost certainly end up creating a 402 "inventory correction" document mislabeled as an issue, exactly the inconsistency the tracker warns against.

## Per-piece QR staleness check

**NOT a forgotten/stale requirement — it is an explicitly open, ALREADY-ACKNOWLEDGED, currently-unresolved scope decision.** The master tracker's own "Otwarte decyzje zakresu" item #1 explicitly names this exact tension and explicitly RECOMMENDS narrowing the demo (pick a part from a list before scanning only the destination location) rather than building permanent per-piece QR identity. No document anywhere calls for building permanent per-piece QR as a long-term architectural requirement.

**The actual inconsistency found**: the master script's own literal text (§7/§9, "Skanuję część albo zestaw") has not yet been updated to reflect the tracker's own recommended narrowing, even though both documents were finalized the same day and the tracker treats the script as its scope source. This is an internal inconsistency within the current master script + tracker pair — a documentation-sync gap, not a stale/reappearing old requirement.

> **RESOLVED 2026-09-23**: this per-piece-QR narrowing note applies to individual PARTS only — it does NOT extend to the container/kit ("zestaw") half of the same sentence. A later, separate 2026-09-10 product-owner directive (`docs/mvp/zones/03-repair-orders-progress.md`, "SCOPE EXPANSION") confirmed the full container workflow, including Container QR (Phase 10D), IS pitch-required — this is a build decision, not a narrowing one, and does not conflict with the per-piece-QR narrowing above (two different physical-identification questions, resolved oppositely, on purpose). The script has now been corrected accordingly: `ambra-skrypt-prezentacji.md` §7 uses list-selection (no part QR) for putaway, and §9 explicitly describes scanning a container's own QR code for relocation.
