## Part 2 — Permission context after branch switch

1. **Fresh per-request, not JWT-dependent**: effective permissions are derived fresh from the DB (`user_effective_permissions`) on every SSR load via `PermissionServiceV2.getPermissionSnapshotForUser`. The JWT carries only a separate, explicitly-labeled-stale `roles` array used purely for UI _display_, with the code's own comment calling this out: "KNOWN STALE WINDOW (G7)... RLS policies check `user_effective_permissions` (always fresh)."
2. `useBranchPermissionsQuery` is confirmed current (name/location accurate) and correctly keyed `["v2","permissions",orgId,branchId]` — a branch switch produces a genuinely NEW cache entry, refetching automatically, not a revalidation subject to staleTime.
3. **SSR re-resolution confirmed**: `changeBranch` persists the new branch server-side; the NEXT SSR load calls `loadAppContextV2()` fresh, resolves the new `activeBranchId`, and calls `loadUserContextV2` with it — no cross-request caching.
4. **Client UI gating updates without logout/reload, confirmed via an explicit bridge**: `PermissionsSync` watches `activeBranchId` in the Zustand store, refetches `useBranchPermissionsQuery`, and pushes the result into `useUserStoreV2` on every change — `usePermissions().can()` reads from that same store and re-renders immediately.

**Concrete scenario, directly answered**: Manager in Branch A, Warehouse Worker in Branch B, switch A→B — **YES, this works correctly today**, full path traced and cited: `changeBranch` validates → Zustand update → `PermissionsSync`'s query key changes → server re-derives permissions scoped to `branch_id IS NULL OR branch_id = 'B'` (correctly EXCLUDING branch A's own UEP rows) → snapshot pushed into the store → `can()` reflects Branch B immediately, no logout. Server-side enforcement doesn't depend on this client cache at all — the next server action independently re-derives the same way.

**This is the permission LAYER specifically** (not general data-display caching, which is a separate, already-tracked set of bugs in `branch-state-cache-inventory.md`) — confirmed correctly branch-scoped.
