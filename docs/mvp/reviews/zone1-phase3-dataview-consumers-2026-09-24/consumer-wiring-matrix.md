## Notes

- All 4 consumers use the identical wiring shape: read `activeBranchId` via the established `useAppStoreV2((s) => s.activeBranchId)` selector pattern (matching `map-list-client.tsx`'s own reference implementation), pass it as the new `branchId` prop to `<DataView>`, leave the existing `queryKey` prop untouched.
- "Branch-aware key?" is verified two ways for every consumer: (a) a dedicated consumer-level test (`*.branch-wiring.test.tsx`) proving the live store value is forwarded and changes correctly when the active branch changes, and (b) Phase 2's own already-passing tests proving the underlying `buildDataViewQueryKey` mechanism produces a genuinely different React Query cache key whenever `branchId` differs.
- "Mutation invalidation status" was determined by grepping all 4 consumer files and their sibling detail/panel components for `invalidateQueries`, `useQueryClient`, and `refreshToken` — zero matches found anywhere across all 4. See `mutation-invalidation-review.md` for the full analysis, including the one discovered (and deliberately unfixed) pre-existing gap.
